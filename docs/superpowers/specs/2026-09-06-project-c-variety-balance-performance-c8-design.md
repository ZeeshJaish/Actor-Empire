# Project C Phase C8 Design — Variety, Balance, Performance, and Long-Run Certification

## Purpose

C8 is Project C's release gate. It adds no new media feature. It exercises the complete canonical week path and verifies that C1–C7 remain varied, bounded, factual, save-safe, and practical for long mobile careers.

## Certification surfaces

### Fresh-save progression

- A no-action new career must advance exactly one calendar week per tap.
- Every processed week must pass the same verified persistence preparation used by autosave.
- Optional generated fields may remain absent without causing save-integrity drift.
- Inactive acquisition systems keep their hidden state current but do not spam the Live Feed with zero-value reports.

### Combined Project C integrity

- B7 remains the canonical fact authority; C1–C7 retain valid event and story lineage.
- Every Project C collection remains inside its existing normalization limit.
- Saved media state survives compaction, JSON round-trip, migration, and resumed simulation.
- News, X, Instagram, and YouTube continue to render the same saved facts rather than generating competing outcomes.

### Variety and balance

Across deterministic industry regimes, retained media must demonstrate multiple story categories, institutions, personalities, channels, creator formats, campaign types, claim types, and narrative themes where qualifying facts exist. No single personality or publication may become the universal voice of the world.

### Long-run and performance

- Reuse B8's completed five-regime, 20,800-week-per-regime canonical certification for the industry facts that Project C consumes but does not mutate.
- Run C1's bounded story layer for 20,800 weeks and run the complete C1–C7 media pipeline across all five regimes for ten years each.
- Verify midpoint save/reload parity on the combined C1–C7 run and bounded compacted save growth.
- This composed gate avoids repeating 104,000 expensive canonical scenario-weeks solely to re-read the same immutable event ledger, while still exercising every Project C processor together.
- Re-run the mature complete Process Week benchmark, including a four-times slowdown mobile proxy.
- Run TypeScript, production build, whitespace, and browser smoke checks.

## Player-visible acceptance

- `Age Up Week` does not stall after quiet early weeks.
- A new career's Live Feed contains meaningful life/game updates, not internal 0% acquisition telemetry.
- Long careers keep a varied media world without unbounded save growth or a single repetitive media voice.

## Explicit limitation

Desktop/browser measurements and the four-times slowdown proxy are engineering gates, not proof of timing on every physical Android device. Physical low-end Android timing remains release-device QA when such hardware is available.
