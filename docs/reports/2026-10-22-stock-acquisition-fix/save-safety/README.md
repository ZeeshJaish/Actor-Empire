# Save safety implementation evidence

The original eight safety cases failed against the old behavior before edits (cash clawback, rewritten basis, dropped corporate allocations, missing repair provenance/recovery and missing integrity coverage). Additional focused failing checks covered unknown historical costs, malformed containers, nonfinite corporate rights and a read-only previous-generation preview. The retained red logs show these failures.

`audit-stock-save-safety.ts` now passes 15 behavior cases. Wallet money is no longer cut to $10T because of an unrelated stock quote. Valid quantities, explicit zero/high historical costs and corporate allocations survive repeat migration. Missing historical costs remain unknown. Quote normalization retains first-original price/history evidence. Unsupported or contradictory positive registers throw `StockSaveRecoveryError` before migration changes anything; the error contains cloned original stocks, portfolio and wallet data and an actionable recovery explanation.

Digest schema 4 protects company-funded share allocations and quote-repair provenance. The schema 1/2/3 verifiers retain their exact historical projections. A frozen schema-3 fixture generated by the pre-change signer pins digest `c96109bd11f0a3d4`; it still verifies while changed protected money does not. The first schema-4 generation retains its original signed schema-3 previous generation, and dropped corporate allocations now trigger verified recovery.

`peekVerifiedPreviousGameData` is read-only and returns a verified previous Player or null. It does not promote or alter generations. The App caller must also test whether that previous player's migration is compatible before offering restoration: a valid historical signature may itself contain an unsupported share register.

Focused save migration, integrity, generation and stock share structure audits pass. The bank/acquisition accounting aggregate also passed, including actual weekly corporate dividend routing and the next week after reload. Tests that formerly required cash clawback or silent corrupt-supply rebasing were intentionally changed to the approved preservation/recovery policy. Generation read-snapshot changes in shared files belong to the root coordinator's concurrent integration repair and were preserved.

No runtime clone change was made for the initially reported callback DataCloneError: the browser harness had used raw week output rather than the application's prepared persisted player. The verification agent corrected that boundary.

Limits: unknown or already-clipped historical balances are not invented; unsafe original register units are not guessed. This evidence is service/storage-generation verification, not a native-device or production-player-save claim. Full stock UI and real IndexedDB evidence is owned by the main flow verification.
